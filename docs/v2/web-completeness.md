## 自动与浏览器检查

2026-10-19 新增账户内 Pro 激活码兑换：只向已登录普通账户显示表单及链动小铺链接，已有 Pro 显示有效期。会员读取使用当前用户的 Supabase 令牌，兑换调用 iTool 的 `/api/pro/redeem`；服务端校验激活码并授予权益。读取失败可重试，兑换期间禁止重复提交，后续会员查询失败不会覆盖已确认的成功回执。

此功能已通过网页构建、lint、67 项测试及模拟接口的浏览器状态验证，包含未登录、普通/Pro 账户、无效码、重复提交、兑换成功、刷新失败和请求中切换账号；检查浅色/深色桌面与 375px 窄屏。没有消耗真实激活码，也没有验证生产 OAuth 或线上兑换。上线依赖 iTool 同步部署 Bearer 鉴权和无凭据 CORS 支持；当前代码完成不代表该后端已部署。

2026-10-28 桌面版新增登录面板（`SignIn.tsx`，本机管理的账号行与工作台「连接你的电脑」共用）：GitHub/Google、邮箱密码、忘记密码与注册跳转 itool.tech、「在浏览器中授权」沿用 `linkshell login` 流程。令牌只经 CLI 写入 `~/.linkshell/auth.json`，页面不持有 refresh token。GitHub/Google 走 PKCE，浏览器回到 `http://127.0.0.1:<端口>/linkshell/callback`，等待 5 分钟。邮箱密码与 PKCE 交换先走 `https://itool.tech/api/linkshell/auth`，不可达或 404 时直连 Supabase。已通过 CLI/Web 单元测试与静态渲染的明暗截图；没有真实登录，没有在 Electron 窗口里操作，本文撰写时 itool-tech 仓库还没有 `/api/linkshell/auth`（另行实现），在它上线前会回退直连。

2026-10-30 修复普通网页 Google/GitHub 登录：点击时同步打开独立窗口，使用固定回调；原标签页按该次 Supabase `flowId` 交换 PKCE code。随机同源 BroadcastChannel 绑定每个窗口，即使提供商的 COOP 移除 opener 仍可返回。回调先清除地址栏 code，不启动工作台、不抢占连接。等待支持取消和五分钟期限，实际账号 HTTP 请求有三十秒中止期限；关闭旧登录面板后，其迟到结果不会关闭新面板。官方网关精确白名单 `https://gateway.itool.tech/?linkshell-auth-callback=1` 已追加，原九条及 Site URL 保留。真实 Google 授权取消的 HTTP 对照验证该 URL 返回 gateway，而根路径和错误 marker 仍被拒绝。Chrome 中本地代码通过实际 Google 已有登录态完成授权、PKCE 交换、弹窗关闭、账号电脑在线发现以及刷新后登录续存；未输入密码或操作账号选择。Web 构建、lint 和 237 项测试通过（含 11 项新增 OAuth 生命周期用例），独立 Review 通过。该证据验证本地新代码与生产认证/网关链路；官方网页新代码尚未部署，GitHub 成功授权与长时间 token 续期未在此次实测。

2026-10-19 的屏幕会话复用把观看页移到应用的稳定挂载位置，保持 iframe 的 DOM 父级、页面和信令 socket。Host 明确支持配置及暂停后，离开详情页即发送暂停；两秒内未确认暂停则关闭观看。120 秒内返回恢复原会话，过期、账号或电脑切换、Host/观看 socket 断开和浏览器页面隐藏会释放旧观看。旧 Host 无能力声明时继续采用配置重连、离页关闭；更改编码或明确重试也重新建立会话。

## 明确的边界

2026-10-19 的屏幕连接反馈优化：网页和手机的启动等待增加屏幕轮廓动画；Host 共用播放器按连接、接收、恢复和错误显示状态，等待超过 12 秒提供重试入口，首帧到达后收起提示。动画遵循减少动态效果设置。浏览器使用模拟连接事件验证明暗主题、390px 窄屏、等待超时、权限错误、断开、重试及原生首帧回调。

2026-10-20 适配当前屏幕会话复用及 Windows 播放器：暂停、配置错误不会被迟到的媒体事件覆盖，配置确认本身不会提前结束首帧等待。浏览器复用夹具通过真实 WebRTC 接收 canvas 画面；离页暂停再返回时，iframe、窗口与接收连接身份不变，启动、offer 和加载次数不增加；断开观看 socket 后显示错误，重试新建连接并恢复画面，底部状态同步更新。125 项 Host 屏幕测试、24 项手机播放/会话租约测试、6 项网页屏幕测试通过；Windows 上根目录构建、全工作区类型检查和 Lint 通过（构建包含 Windows helper，按平台跳过 Mac）。这些检查不代表真实远程采集、手机真机或公网验收；此前全量 Host 测试在 Windows 符号链接权限检查处受限，没有宣称完整 Host 测试集通过。

2026-10-14 的命名与布局验收使用六台模拟电脑，覆盖同名、离线、缺少权限、屏幕连接失败状态；浏览器验证了保存/取消/恢复原名、刷新保留、长名称、回车提交、搜索、画质浮层、列表进入独立详情、详情刷新、浏览器返回和返回列表按钮，以及专注/全屏/停止、桌面明暗主题和 390px 窄屏。Web 构建、lint 和 48 项测试通过，包含设备身份在详情 URL 中的编码回归。本轮未重新验证真实屏幕媒体或跨设备同步。

1. 生产 OAuth 回调白名单、令牌续期、真实 Codex/Claude/ACP 行为、公网弱网和长期运行仍需各自环境验证。模拟 Agent 不作为这些能力的生产证明。
2. 端口预览不是通用浏览器代理。外部 OAuth、绝对 loopback 地址、站点自带 Service Worker、完整 Cookie 语义仍有限制；WebSocket 握手尚未携带 HTTP 预览 Cookie。
3. 屏幕 iframe 的“读本机剪贴板”仍受浏览器 Permissions Policy 限制；输入文字/键盘控制与快捷键不等于完整的双向剪贴板。没有放宽 iframe sandbox。
4. 终端已接入 Host 快照恢复，同时兼容录制帧回放；极长历史的恢复时间和长时间压力测试尚未独立验证。
5. 文件暂无线框协议支持的通用重命名/删除操作。文件预览现可通过 `fs.download` 分块下载原文件（包括无法预览的图片、视频和其他二进制文件），需要同步更新 Host。支持保存位置选择的浏览器逐块写入文件；其余浏览器使用 Blob 下载，上限 256 MiB，防止占用过多内存。ACP 编辑建议的真实供应商行为仍需实际 Agent 验证。
6. 会话分页使用现有 Host 的时间戳游标。边界处同一毫秒的大量记录仍有该协议本身的限制，不能宣称无限规模下完全无遗漏。
7. HEVC、120 fps 和高分辨率都受浏览器、显示器、编码器与网络影响；本轮不能证明稳定 120 fps 或与 iPhone 完全等效。

因此当前结论是：主要工作流已接通，并对本轮发现的阻断缺陷完成修复及相应验证；尚不等于所有场景与手机 100% 功能/性能等价。发布与上线须遵循根目录的 LinkShell 发布规则，不由本地构建状态推断。
