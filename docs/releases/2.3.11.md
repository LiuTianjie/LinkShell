# 2.3.11 · CLI 0.10.12

## 改动

- 远程屏幕直连（视频轨）可以选清晰度：「连接信息」里的流畅 1280 / 标准 1920（默认）/ 高清 2560 / 原生（屏幕本身的宽度，最高 3840）。切换时重新连一次，模式不变。中继和兼容方式仍按网络自动调整，不受这个选项影响。
- 帧率不变：60 帧，网络或编码跟不上时自动降到 30，好转后回到 60。
- LinkShell.app 的码率上限随分辨率增长（1920 宽 60 帧 12 Mbit/s，2560 宽 16 Mbit/s，4K 24 Mbit/s，最高 30 Mbit/s），实际码率仍由带宽估计决定。
- App 记住上次选的清晰度。

## 验证

- `pnpm build`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm --filter @linkshell/mac check` 通过。`claude-handoff.e2e.test.ts` 里「sends a waiting message at once…」一条在改动前后都约 3/10 偶发失败，与本次无关。
- 本机（5K 显示器）用构建出的 LinkShell.app + 源码 host + 无头 Chrome 打开观看页：1920 / 2560 / native 分别收到 1920×1080、2560×1440、3840×2160 的视频轨，码率上限 12M / 16M / 24M；在页面里点「流畅」后重新加载为 1280×720，模式保留。
- loopback（移动文字窗口）：2560 宽 glass→decoded p50 28 ms，编码 15.7 ms/帧；3840 宽 p50 46 ms，编码 23.6 ms/帧，60 帧跟不上，自动在 30 帧附近。
- 未在真机手机上验证清晰度切换。

升级后需重启 Host（`linkshell host stop && linkshell host --daemon`）。
