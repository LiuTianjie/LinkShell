# Mac 桌面工作台

## 产品目标

LinkShell.app 同时是这台 Mac 的 Host 管理工具和控制其他电脑的客户端。启动后进入工作台，能够继续对话、处理审批、使用终端与文件，并打开其他电脑的远程桌面；本机权限、服务、日志、用量与更新保留在原生「本机管理」中。

桌面视觉与 StupidMirror 同一套系统（2026-10-22 重构，按 taste-skill 的 app-screen 流程定稿，风格 `true-black-flat`）：窗口是灰色底，面板比底色深一档（深色）或浅一档（浅色）并带一条细边，面板内再用一档“井”承载列表、代码和设置；没有渐变、发光、亮边或静止阴影，只有浮起的菜单、对话框和 ⌘K 带阴影。颜色只表示状态：Agent 运行中是品牌薄荷绿，等你处理是琥珀色，出错是红色，已完成保持灰色。每屏唯一的实心按钮是反色胶囊（深色白底黑字、浅色黑底白字）。只用系统字体，路径、分支、端口和版本用等宽字。令牌在 `apps/web/src/theme.ts` 与 `apps/mac/Sources/LinkShell/DesktopTheme.swift` 两处，取值一致。

窗口按开发工具的方式分区（参考 ZCode）：最上方 46 pt 顶栏由原生绘制，与红绿灯同一行，放品牌、「工作台 / 本机管理」切换（⌘1 / ⌘2）、居中的「搜索会话、项目和命令 ⌘K」，以及这台 Mac 的服务、网关、待确认请求和新版本提示；顶栏也是窗口的拖动区。下方左侧是 264 pt 侧栏面板：电脑切换、新建会话（⌘N）与搜索、七个去处（会话、项目、远程桌面、终端、文件、端口预览、Worktree），然后是「需要你」和按项目分组的会话树（运行中显示转动的薄荷色圈，等你处理显示琥珀点），⌘B 收起。中间是主面板；打开会话时右侧再出现检查器面板。窗口最下方是状态行：当前电脑、连接方式、Host 版本、需要你与进行中的数量。Windows 没有原生顶栏，由页面画出同样的一条。

会话页的标题栏只放会话标题、状态、Agent、项目和分支，以及变更、文件、终端、预览四个检查器开关和更多菜单。检查器是一块可拖动调宽（320 pt 到窗口 62%，宽度会记住）的独立面板，标签为变更、文件、终端、任务、预览、设置；目标、MCP、应用打开时临时加一个标签。终端从弹窗改为检查器标签，⌘J 打开，⌥⌘B 显示或隐藏检查器；窗口窄于 1100 pt 时检查器浮在对话上方。会话列表页标题下直接写出“几项在等你、几个在跑、今天几个会话”，去掉了原来的四张统计卡；已归档从侧栏移到列表页右上角和 ⌘K。电脑与 Agent 管理放在电脑切换菜单和 ⌘K 里。⌘K 同时搜索会话、项目（选中即在该项目新建会话）、去处、电脑与外观，并列出全部快捷键；⇧⌘[ / ⇧⌘] 在侧栏会话间切换，⌘[ / ⌘] 后退前进。快捷键表在 `apps/web/src/live/desktop-commands.ts`，控制远程桌面时按键仍然交给那台电脑。本机管理沿用同一套面板：侧栏列出页面，总览把服务、网关、屏幕权限和设备合成一块分栏的状态井，设置按“外观与启动 / 让手机查看和控制这台 Mac / 数据 / 命令行工具”分组。

桌面端口预览支持多个标签：切换时保留各自的预览，刷新和关闭只作用于对应标签。「铺满窗口」在当前 App 内展开预览，并提供明确的退出操作。远程桌面专注观看、全屏和端口预览铺满窗口时，通过受信任的状态消息隐藏原生顶栏和页面的状态行，不重建 WKWebView；退出后恢复。

## 参考取舍

查看了 [ZCode](https://github.com/zai-org/ZCode) 的界面结构与 Agent 连接实现（参考版本 `0a1fc56d`）。借鉴其清晰的工作区域和断线后保留对话上下文的处理：历史与草稿留在原位置，订阅恢复后再开放发送、审批和会话设置。ZCode 当前主要协议实现并非可直接替换 LinkShell 的 ACP 层，因此继续使用现有 Codex / Claude / ACP drivers、wire 和加密通道；未复制其代码或视觉资产。

## 实现分层

1. **原生窗口。** AppKit 管理窗口、菜单栏、工作台/本机管理切换和外链；单个长期存活的 WKWebView 承载工作台。系统浏览器完成既有 iTool 登录。
2. **共享业务与原生媒体。** 桌面复用 Web 的会话、审批、终端、文件、项目，以及 `client-core` / `wire` 的状态与加密通道。屏幕导航、工具栏和既有加密信令留在 Web；画面由 Mac 原生 WebRTC、VideoToolbox 与 Metal 接收显示，输入由 AppKit 处理。桌面专属 Shell 和样式负责布局与质感，不重建一套协议。
3. **随包工作台。** `build-app.mjs` 将当前工作台源码直接构建到签名 bundle 的 `Contents/Resources/Workspace`；首次打开无需下载远程网页。独立桌面版和 CLI 管理的 helper 使用相同产物。
4. **桌面适配服务。** App 启动配套 CLI 的 `desktop-workspace --assets <dir>`，只监听随机的 IPv4 loopback 端口。就绪握手从 stdout 返回；stdin EOF、退出或终止时取消尚未完成的账号和登录请求，结束监听和本次连接，并等待持久化队列完成，不停止 Host。
5. **两种电脑连接。** 本机走受保护的 Unix socket WebSocket 代理，不需要账号、Pro 或网关；首次发现按 0.5、1、2、4、8 秒的有界退避补查，兼容独立版 Host 晚于工作台就绪。其他电脑继续通过网关上的独立 device 身份、配对或同账号发现、端到端隧道连接。

## Mac 原生屏幕接收

`DesktopScreen.tsx` 连接既有屏幕信令与原生桥。`DesktopScreenReceiver.swift` 管理原生 WebRTC 连接和 DataChannel；`DesktopScreenDecoder.swift` 创建 VideoToolbox 解码会话，设置 `RequireHardwareAcceleratedVideoDecoder`，并查询会话的实际 `UsingHardwareAcceleratedVideoDecoder` 属性。`DesktopScreenSurface.swift` 持有 IOSurface 像素缓冲区，经 `CVMetalTextureCache` 映射为纹理后交给 Metal 显示。解码后的视频帧不进入 WebKit 或 JavaScript。

AppKit 原生视图负责鼠标、键盘与输入法，通过屏幕 DataChannel 发送控制事件。H.264 是桌面默认编码；解码器具备 H.264 和 HEVC 支持，不把后者视为桌面界面已完成 HEVC 协商。硬件不可用或媒体连接失败时，界面显示具体错误和重试入口，不切换软件解码、Web 播放器或字节流降级。

首版在离开观看页、切换本机管理或窗口关闭、隐藏时销毁屏幕连接并释放输入，返回后重新连接。普通 Web/iOS 的 120 秒暂停复用规则不适用于这条 Mac 原生路径。

## 状态与权限

- 客户端身份与 Host 机器身份分开。`LINKSHELL_HOME/desktop-client.json` 保存设备身份、配对、电脑名称、草稿与界面偏好，文件权限为 `0600`。随机端口或 App 重开不会制造新设备。
- 工作台与本机管理共用 CLI 的账号。工作台只获得短期 access token，refresh token 留在 CLI。客户端登录不要求启动本机 Host。
- 桌面 API 同时校验随机凭证、精确 Host 和 Origin；不开放 CORS。Unix socket 代理拒绝 `desktop.*` 和未知 RPC。工作台入口不是 Host 的 `--dev-port`。
- 原生消息桥只接受可信 loopback 顶层页面。外链交给系统浏览器；端口预览使用另一 origin，不能调用原生桥或读取桌面凭证。Mac 远程画面由原生视图承载，普通浏览器仍保留既有隔离 iframe 路径。
- 关闭窗口、最小化或进入本机管理会通知页面停止观看、释放输入。保留会话和草稿；返回工作台重新建立需要的屏幕会话。
- 草稿与设置写入按队列提交，失败项保留以便重试。正常退出 App 或重新连接工作台前，原生调用页面的 flush 接口，等待队列清空与保存确认；失败或超时提供返回工作台与明确继续两种选择。确认退出后才关闭工作台 sidecar，本机 Host 按原有规则继续运行。
- 接收远端画面不需要授予这台 Mac 的屏幕录制或辅助功能权限。只有将这台 Mac 作为受控电脑时才需要这些权限。

## 验收范围

检查桌面 API 的访问边界、重开后的持久化、本机连接与远端配对；在实际 WKWebView 中检查会话、原生切换、主题与外链，并单独验证原生屏幕输入、解码、显示和连接生命周期。新增 Mac 媒体路径需要确认 VideoToolbox 实际使用硬件、Metal 呈现及回环交互；本轮已通过实际硬件解码属性与原生 WebRTC 回环测试，并在实际 App 中确认 Metal 出画、窗口内铺满及控制状态。静态构建和模拟 Agent 联调不代表生产 OAuth、真实 Agent、公网媒体或长时间性能验收。

本轮具体执行结果记录在 [Mac 桌面说明](../../mac-desktop.md) 的工作台验证段。发布、公证、DMG 和 Sparkle 上线属于独立发布流程。
