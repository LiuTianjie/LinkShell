# LinkShell 视觉规范

手机 App（`apps/client`，含 Watch 和 Live Activity）、桌面端（`apps/web` 的 `html[data-desktop]` 和 `apps/mac` 的原生窗口）、网页控制台（`apps/web` 在浏览器里）和官网（`docs/site`）都照这一份做。改视觉先改这里，再三端一起改；不要只改一端。

它取代了之前分散的几个方向：`apps/web/AGENTS.md` 里的“参照 Linear”、桌面端注释里的“参照 Codex”、原生窗口的薄荷绿、官网的青绿。Linear、Codex 可以作为克制和精确的参照，但颜色和尺寸只用这里的值。

## 原则

- **颜色只说两件事**：能操作（品牌靛蓝）和状态（运行、等你、出错）。其余一律中性灰。
- **不做装饰**：没有皮肤、主题图案、呼吸灯、涟漪、扫光、渐变、光晕、emoji。屏幕上唯一的彩色图形是 Agent 自己的标志（`agent-marks.ts`），保持原样。
- **按平台的习惯来**：手机用 iOS / Android 的系统中性色、控件形态和反馈；桌面用桌面密度。各端统一的是品牌色、状态色、几何规则，以及审批这类关键组件的结构和文案。
- **一件事一个样子**：同一个状态、同一种操作，在每一端颜色、位置、叫法都一样。

## 颜色

唯一来源：[`apps/client/src/theme/brand-colors.json`](../../apps/client/src/theme/brand-colors.json)。`apps/web/src/theme.ts` 直接读它，Android 资源由 `with-brand-colors.js` 生成；Swift（`DesktopTheme.swift`、`WatchModels.swift`、Live Activity）和官网 CSS 抄同样的值，`apps/web/test/brand-colors.test.ts` 检查它们没有走样。

| 用途 | token | 浅色 | 深色 |
| --- | --- | --- | --- |
| 可操作的文字、图标、链接、选中、焦点环 | `accent` | `#4c5fd5` | `#8d9bff` |
| 主按钮底色（上面是白字） | `accentFill` | `#4c5fd5` | `#5263e8` |
| 主按钮悬停（桌面） | `accentHover` | `#4254c7` | `#4d5fe0` |
| 选中行、浅底 | `accentSoft` | `rgba(76,95,213,0.10)` | `rgba(141,155,255,0.16)` |
| 运行中 | `running` | 同 `accent` | 同 `accent` |
| 等你处理（审批、提问、等输入） | `waiting` | `#ad5200` | `#ffad5c` |
| 等你处理的按钮底色（白字） | `waitingFill` | `#ad5200` | `#b25600` |
| 等你处理的浅底 | `waitingSoft` | `rgba(173,82,0,0.10)` | `rgba(255,173,92,0.14)` |
| 明确的成功（提交成功、勾选、新增行） | `ok` | `#187a4a` | `#4cc38a` |
| 成功浅底 | `okSoft` | `rgba(24,122,74,0.10)` | `rgba(76,195,138,0.14)` |
| 出错、危险操作 | `danger` | `#c8322f` | `#ff7b72` |
| 出错浅底 | `dangerSoft` | `rgba(200,50,47,0.09)` | `rgba(255,123,114,0.14)` |

文字色的值在浅色背景和深色背景上对比度都不低于 4.5:1；白字只放在 `accentFill`、`waitingFill`、`danger`（浅色）上，不放在深色模式的文字色上。

中性色按平台：iOS 用系统语义色（`colors.ts` 已经这样做），Android 用 `brand-colors.json` 里同名的字面值，桌面和网页控制台用 `theme.ts` 里各自的中性色。

### 状态

| 状态 | 颜色 | 叫法 |
| --- | --- | --- |
| 运行中 | `running` | 运行中 |
| 等你批准 / 回答 | `waiting` | 等你处理（分得清时写“等你确认”或“等你回答”） |
| 出错 | `danger` | 出错 |
| 空闲、已完成 | `tertiaryLabel`（灰） | 空闲 |
| 离线、状态未知 | `tertiaryLabel`（灰） | 离线 |

空闲和完成是常态，不用绿色。会话状态里绿色只给一次明确的成功。

电脑和本机服务的连接状态另算：在线、服务正常用 `ok` 绿点；离线、未运行用灰；连接出错用 `danger`；正在连接用转圈加 `secondaryLabel` 文字。Pro 这类会员标记是中性徽标（`fill` 底、`label` 字），不上色。

## 几何

### 桌面端、网页控制台、Mac 原生窗口

- 圆角：`4` 小件（徽标、按键提示、行内代码、复选框）；`6` 控件（按钮、输入框、下拉、菜单项、列表行、标签页）；`8` 容器（卡片、弹出层、菜单、代码块、审批卡、提示条）；`12` 大容器（对话框、侧滑面板、检查器、原生窗口里的面板）。
- `999px` 只用于状态点、头像、开关轨道、滚动条和计数徽标。按钮不做成胶囊。
- 控件高度：`28` 紧凑（工具栏、图标按钮 28×28），`32` 默认（按钮、输入框）。
- 字号：`11` 只给按键提示和计数徽标；`12` 次要信息（时间、路径、说明、表头）；`13` 界面默认（列表标题、菜单、按钮、表单、侧栏里的会话行）；侧栏一级导航沿用 `14`、行高 40；`14` 正文（对话、Markdown、对话框正文）；`16` 对话框和面板标题；`20`、`24` 页面标题。不用 `10px`，不用 `11.5`、`12.5` 这种半号。字重只用 400、500、600。
- 间距取 4、8、12、16、24、32。
- 阴影只给弹出层和对话框（`--shadow-popover`）；卡片是平的，靠细线分隔。
- 图标：Lucide 圆角线条，1.75 描边，控件 16、导航 18、箭头 12（见 `desktop.css`）。

### 手机

- 圆角（`theme/type.ts` 的 `radius`，连续圆角）：`chip 8`（徽标、标签、行内代码）；`control 12`（输入框、分段控件、小图块）；`card 16`（列表分组、卡片、需要处理的卡片）；`panel 24`（分栏面板、大浮层）。按钮是胶囊（高度的一半），跟 iOS 26 一致。不写散落的数字，都用这几个 token。
- 字号只用 `theme/type.ts` 的 `type.*`；只有代码、终端用等宽字号。`caption2`（11）只给标签栏和计数徽标。
- 图标：iOS 用 SF Symbols，Android 用 Material Symbols，跟随系统字重。

## 反馈和动效

- 按压：手机上列表行按下时底色变成 `fill`，按钮按下时降到 60% 不透明，不缩放。原生 Glass 控件保留系统自己的反馈。桌面悬停用 `fill`，按下用 `fillStrong`，不缩放。
- 状态变化 120–200 ms，ease-out。
- 可以一直动的只有三种：进行中的转圈（1 s 一圈，匀速），加载占位的扫光，正在输出时的那一行文字（桌面的文字微光、手机的三个点）。不用脉冲、呼吸、涟漪、扫描线。
- 状态点是 8 px 的实心圆，不发散。
- 跟随系统的“减弱动态效果”。

## 关键组件

### 审批卡

三端同一个结构：

1. 标题：Agent 要做什么。
2. 细节：命令或路径，等宽字体，放在 `code` 底色的块里。
3. 按钮：选项一律经过 `permissionChoices`（`packages/wire/src/live-activity.ts`），显示中文名，顺序是 拒绝 → 允许 → 始终允许 → 停止。只有“允许”是实心主按钮（`accentFill`），其余是次要按钮；“拒绝”不用红色。桌面按钮高 32、圆角 6。

### 电脑卡片

只有一种样子：CPU 和内存的读数，加一条最近的历史曲线（CPU 用 `accent`，内存用中性灰）。不提供样式切换。

### 空状态

一个系统图标（`secondaryLabel` 色，不加底色方块）、一行标题、一句说明、最多一个按钮。

## 改动时

- 先改这份文档和 `brand-colors.json`，再改各端。
- 改完跑 `pnpm build`、`pnpm typecheck`、`pnpm test`，并在浅色和深色下各看一遍受影响的界面。
